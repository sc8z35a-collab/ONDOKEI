# Battery Relay 設計

## 構成

- `MonitorService`: ユーザー可視のフォアグラウンドサービス。通常15秒、Turbo 5秒、保護時60秒で公開 API を読みます。
- `MeasurementRepository`: 計測、1分バケット保存、UI 通知を直列化します。Turboのライブ点はメモリで置換し、DB書き込みを最大1回/分に制限します。
- `HistoryStore`: SQLite の1分バケット。書き込み／読み出しのたびに30分超を削除し、最大31行へ制限します。
- `MainActivity`: 上部の端末タブ、即時更新、Turbo切替、分単位変化率、2本の30分グラフを描画します。
- `ShareHost`: ローカル TCP サーバー、DNS-SD 公開、ペアリング、暗号化スナップショット応答を担当します。
- `NsdBrowser`: `_batteryrelay._tcp.` を検索します。Android 14以降は継続的なサービス情報コールバック、旧版は再試行付き直列名前解決を使います。
- `RemoteDeviceManager`: 最大8接続をApplicationスコープで所有し、表示切替やActivity再生成で切断しないよう管理します。
- `RemoteClient`: 選択中は通常15秒/Turbo 5秒、非選択またはUI非表示中は60秒で暗号化スナップショットを取得します。

## データ保持

1. 通常15秒/Turbo 5秒で読み、`timestamp / 60000` の1分バケットへ保存します。
2. 同じ分のライブ値はメモリで置換し、次の分へ移る際に前の分の最終値を永続化します。
3. `captured_at < now - 30min OR captured_at > now` をトランザクション内で削除します。
4. 時刻変更などの異常時にも最大31行を超えないよう二次制限します。
5. 共有元は送信直前、共有先は復号直後にも30分窓を再適用します。
6. 共有先の履歴はメモリ上だけで、次回スナップショットに置換されます。

## 分単位変化率

直近の有効点と、30秒以上前にある直前の有効点を探し、次式で計算します。

`rate = (newValue - oldValue) / ((newTime - oldTime) / 60000)`

固定60秒と仮定しないため、OS のスケジューリング遅延があっても `/分` の値が歪みにくい設計です。温度が取得不可の点は温度レートだけから除外します。

## 共有プロトコル v1

### 発見

共有元は Android Network Service Discovery で TCP ポート、共有 ID、16バイト salt、P-256 公開鍵を広告します。共有データは DNS-SD TXT へ載せません。待受と共有先ソケットは検出したWi‑Fiの `Network` へ固定し、Wi‑Fi切替時はセッション鍵を保持したまま再バインド・再広告します。

### ペアリング

1. 共有先が一時 P-256 鍵ペアを生成します。
2. ECDH 共有秘密を計算し、共有 ID と画面上の128ビット共有キーを HKDF-SHA-256 のコンテキストへ含めて一時鍵を導出します。
3. 共有先は AES-256-GCM で認証されたペア要求を送ります。コードそのものは送りません。
4. 共有元は認証成功時だけ、ランダムなセッション ID と256ビットセッション鍵を暗号化応答します。

### スナップショット

各要求はセッション単位の単調増加 `seq` を持ち、要求／応答の AAD にも含めます。共有元は再利用または逆行した番号を拒否します。時刻同期には依存しません。

画面の「更新」から送る要求だけが暗号化済みの `fresh` フラグを含みます。共有元は応答直前にAndroid公開APIを再読込します。定期ポーリングは共有元の最新キャッシュを使うため、共有元端末へ二重の測定負荷を与えません。

## 電力・熱ポリシー

| 状態 | ローカル測定 | 選択中の共有先 | 非選択/画面非表示の共有先 |
|---|---:|---:|---:|
| 通常 | 15秒 | 15秒 | 60秒 |
| Turbo | 5秒 | 5秒 | 60秒 |
| 省電力または熱状態「重度」以上 | 60秒 | 60秒 | 60秒 |

ローカル測定はWakeLockを取得せず、画面消灯時にOSがプロセスを実行しなければタイマーは自然に遅延します。測定、共有待受、暗号処理、接続処理はバックグラウンド優先度です。通知とSQLiteの更新は1分に1回までです。明示的な「計測を停止」では共有元・共有先の全セッションを破棄しますが、端末タブを切り替えるだけでは破棄しません。

### 防御上限

- 受信1メッセージ: 共有元8 KiB、共有先24 KiB、JSON深度8
- 接続タイムアウト: 5秒、共有元読み取りタイムアウト: 1.5秒
- 認証前同時接続: 全体8、送信元IPごと1（超過は即時拒否、待ち行列なし）
- TCP受付: 送信元IPまたはIPv6 /64ごとに1分120回まで
- ペアリング試行: 成否を問わず1 IP あたり1分に5回まで
- 認証済み取得: セッションごとに1分30回まで、即時測定は全体・セッションごとに最低5秒
- 同時閲覧セッション: 8
- セッション: 最終利用から2時間で失効
- 128ビット共有キー: 5分ごとに更新
- 取得失敗: 鍵を保持したまま最大60秒の指数バックオフと障害時DNS-SD再解決

## Android 互換性

- `minSdk 26`（Android 8.0）、`compileSdk/targetSdk 36`
- Android 13 以降では通知権限を要求します。
- Android 10 以降で OS thermal status を追加表示します。
- Android 14以降は継続更新型NSD APIでアドレス変更を追跡し、旧版は低頻度の再解決を継続します。
- Android 17 のローカルネットワーク権限変更に対しては target 36 の互換動作を利用します。target 37 へ上げる際は `ACCESS_LOCAL_NETWORK` の実行時許可フローを追加する必要があります。

## 非目標

- CPU/SoC 温度の推測や `/sys` のベンダー依存読み取り
- インターネット越しの共有
- クラウドアカウント、ユーザー追跡、恒久履歴
- 医療・安全機器としての利用
